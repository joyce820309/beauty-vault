# Feature Spec: Detail 頁「查看今日匯率」

## 文件狀態
- 狀態: Draft
- 建立日期: 2026-07-17
- 適用頁面: 採購清單 Detail 頁（金額區塊）
- 本文件目的: 先釐清需求與驗收方向，不進行程式實作

## 1. 背景與目標
目前採購清單金額以 TWD 記錄，但使用情境可能發生在國外購買。使用者希望在 Detail 頁面可快速查看「當日匯率換算後」的多幣值金額，協助當下判斷是否划算。

## 2. 使用者故事
- 身為常在國外購物的使用者，我希望在商品明細看到一鍵查看當日匯率，讓我不用離開 App 也能估算外幣金額。
- 身為採購紀錄維護者，我希望這功能只做參考換算，不改動原始記錄金額（TWD）。

## 3. 功能範圍（MVP）
- 在 Detail 頁的金額欄位附近新增「查看今日匯率」按鈕。
- 僅在已有金額時可使用該功能。
- 點擊後顯示:
  - 原始金額（TWD）
  - 匯率日期（當日）
  - 多個目標幣別換算結果（例如 USD / EUR / JPY / KRW）
- API 失敗時顯示友善錯誤訊息，且不影響 Detail 頁其他操作。

## 4. 非目標（本期不做）
- 不將外幣結果寫回資料庫。
- 不改動原有金額欄位資料型態與主流程。
- 不做跨日歷史回溯分析（先以「當日查詢」為主）。

## 5. 匯率 API 選型結論（先行決策）
建議優先採用 Frankfurter。

理由:
1. 免 API key，前端整合成本低。
2. 免費支援日期查詢與歷史資料，後續若從「當日」擴展到「購入日」不需換服務。
3. 無月配額說明（僅防濫用 rate limit），搭配快取可穩定使用。
4. 支援 base 與多幣別查詢，符合本功能需求。

備選: open.er-api
- 優點: 免 key、文件成熟。
- 限制: Open 端點需 attribution；歷史匯率屬付費功能。

## 6. 資料與計算規則
- 原始金額來源: 現有 Detail 資料（TWD）。
- 換算公式: converted = amount_twd * rate(TWD -> target_currency)
- 顯示精度: 待定（預設可先 2 位小數；JPY 可考慮 0 位）。
- 日期語意: 待定（台灣時區日界線 vs API 回傳更新時間）。

## 7. UI/互動需求
- 按鈕文案: 查看今日匯率
- 觸發條件:
  - 有金額: 可點擊
  - 無金額: 按鈕 disabled 或不顯示（待定）
- 顯示容器: 區塊展開或彈窗（待定）
- 必要資訊:
  - 匯率基準日期
  - 資料來源提示（若服務條款要求）
  - 免責說明（僅供參考，非實際結算）

## 8. 錯誤與離線策略
- 網路失敗: 顯示「目前無法取得匯率，請稍後再試」。
- API 限流: 顯示「查詢過於頻繁，請稍後再試」。
- 快取策略（建議）:
  - 同一 base 與同一天結果進行本地快取。
  - 有快取時可先顯示快取，再背景更新（待定）。

## 9. 驗收條件（Draft）
1. 金額存在時，Detail 頁能看到「查看今日匯率」入口。
2. 點擊後可看到 TWD 原始金額與至少 3 種外幣換算值。
3. 顯示匯率日期與資料更新資訊。
4. API 失敗不影響頁面主流程且有明確錯誤訊息。
5. 原始金額欄位資料不被改寫。

## 10. 待確認清單（你拍板後即可實作）
1. 目標幣別清單固定或可自訂？
2. 顯示精度規則（全部 2 位，或依幣別）？
3. 當日定義時區（台灣時區或 API 時間）？
4. 無金額時的 UI（disabled / 隱藏）？
5. 顯示形式（inline 展開 / modal）？
6. 是否要顯示並保留「上次快取匯率」？
7. 是否加上「僅供參考，實際以刷卡/店家為準」說明？

## 11. 後續延伸（非本期）
- 以購入日自動帶入歷史匯率，提供「當日 vs 購入日」比較。
- 允許使用者自訂常用幣別與排序。
- 匯率趨勢小圖（7/30 天）協助判斷購買時機。
